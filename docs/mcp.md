# Integration API and MCP

Verified deployed endpoints: [production MCP](https://tasks.abuk.in/api/v1/mcp) and [dev MCP](https://d38hszs898xc3y.cloudfront.net/api/v1/mcp). Each requires a scoped token from that environment's Integrations page. Live initialization, discovery of all 11 tools, reads/writes, permission denial, and revocation passed on 2026-10-07.

Integrations are opt-in. Sign in to your workspace and open **Integrations** to create a credential. Give it a name, choose only the permissions it needs, and set an expiry of 1–90 days. The token is shown once; the server stores only its SHA-256 hash. The same page lists credentials, provides a recent audit log, and can revoke a credential immediately. Creating or revoking a credential requires a same-origin authenticated browser request. No credential is created automatically.

All credentials belong to the workspace that issued them. A credential cannot select another workspace. Permissions are `projects:read`, `tasks:read`, `tasks:write`, `sprints:read`, and `sprints:write`. Reads and writes check permissions on every request. Sprint snapshots omit task contents unless the credential also has `tasks:read`. Revoked and expired credentials are rejected.

Use the token as `Authorization: Bearer <token>` for the REST API under `/api/v1/integrations`. Available reads are `GET /workspace`, `/projects`, `/tasks`, `/tasks/:id`, and `/sprints`. Task search supports `q`, `projectId`, `statusId`, `priority`, `sprintId`, `label`, `dueBefore`, `dueAfter`, `archived`, `page`, and `limit`. Write with `POST /commands/:action`, where action is one of `task.create`, `task.update`, `task.move`, `sprint.create`, `sprint.start`, or `sprint.complete`. Use the domain command input as JSON.

Every write requires `If-Match: "<revision>"` and a unique `Idempotency-Key` header of 8–100 characters. Read responses provide the workspace revision. A retry with the same key and input returns the original result. A stale revision returns HTTP 409. The same atomic revision and retry rules apply to browser commands, REST integrations, and MCP tools.

The MCP adapter uses the official Model Context Protocol SDK and stateless Streamable HTTP at `POST /api/v1/mcp`. It returns JSON responses instead of keeping SSE connections open, so it runs within the same buffered Lambda as the REST API without a separate always-on server. There is no MCP license, subscription, model call, or per-tool fee. AWS hosting still follows the account's usage-based pricing and allowances; free access does not guarantee a zero AWS bill.

The local `.env` and the dev/prod AWS templates set `MCP_ENABLED=true`. The generic `.env.example` keeps explicit opt-in for other deployments. After deployment, the CloudFormation `McpUrl` output is the HTTPS endpoint. Connect a trusted Streamable HTTP client using that URL and `Authorization: Bearer <token>` from a credential created in the Integrations page. Clients must accept `application/json, text/event-stream` and send the negotiated `MCP-Protocol-Version` after initialization. GET returns 405 because this service does not offer a persistent SSE stream. Stateless calls need no sticky session or MCP session ID. Tokens belong to one environment/workspace and have explicit permissions, expiration, and revocation.

Available tools are `list_projects`, `list_tasks`, `search_tasks`, `read_task`, `list_sprints`, `create_task`, `update_task`, `move_task`, `create_sprint`, `start_sprint`, and `complete_sprint`. Write tools require `input`, `revision`, and `idempotencyKey` arguments. Read tools include the revision needed for later writes. Both protocols use the same credential checks and domain rules. Clients that require legacy SSE or OAuth discovery need a separate compatibility implementation; the currently verified transport uses scoped bearer authentication and standard Streamable HTTP JSON.

The audit log records the actor, action, time, outcome, and error code. Successful workspace mutations also record the credential actor alongside the domain activity within the same atomic write. Neither token nor request payload is written to the audit log.
